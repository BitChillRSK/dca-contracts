Rules:
- **7A does not edit any handler file.** Every ghost that a handler must update gets a hook function in `Base.sol`, for example `_ghostDonateStable(h, amt)`, and 7B places the call. Section 9 lists which hook goes in which handler. Two exceptions: 7A updates `_trackSchedule` / `_untrackSchedule` in `Base.sol` directly, and those cover `schedulesCreated`, `schedulesDeleted`, `maxIdSeen`, `deletedIds` and `deletedTokens`.
- **7B does not edit `Base.sol` or `Snapshots.sol`, or the Global section of `Properties.sol`.** If 7B needs another snapshot field or helper, it computes the value locally in memory inside the wrapper. It must not add the field to the shared structs.
- 7A must leave the suite compiling, and `FoundryTester.test_harnessFlow` must pass with the global properties in place. Add a Foundry test `test_globalsHold()` to `FoundryTester.sol`; it is the one handler-adjacent edit 7A may make. The test runs `test_harnessFlow`'s sequence and then calls every `property_*` GL function.
- Checkboxes in `PROPERTIES.md`: 7A flips GL-*; 7B flips SP-*. If a property cannot be implemented, mark it `[-]` and add a one-line reason. Do not delete it.

Global-property rules (7A):
- Loops are bounded by `actors` (3), `_accounts()` (4), `routes` (5), `dexHandlers` (2), `trackedSchedules` (≤ `MAX_TRACKED`, see below) and the `deletedIds` tail (last 64 entries).
- Wrap every external getter that can revert in try/catch: `getDcaSchedule`, `getAccruedInterest`, `getDcaSchedules`, and anything in a loop. A caught revert becomes `t(false, "<ID> getter reverted")`, never a silent revert. Medusa's property mode treats a revert as a failure that comes without a message.
- `failOnArithmeticUnderflow` is **false** in `medusa.json`. A checked-arithmetic underflow inside a property therefore reverts silently and **hides a violation**. Before any subtraction, assert the order with `gte`/`lte`, or compute signed deltas with `int256`. This applies to 7B as well.
- `MAX_TRACKED = 64`. 7B's create paths (clamped wrapper, ADV-18, ADV-05) return early when `trackedSchedules.length >= MAX_TRACKED`, so snapshot and global-loop gas stays bounded.

## 10. Gotchas for both implementers

1. **Underflow hides violations** (`failOnArithmeticUnderflow: false`). Assert the order before you subtract, or use `int256`.
2. **Window reachability**: the `medusa.json` block delay makes cross-call windows rare. H3's single-call scenario and `env_skipBlocks` are how the window properties get exercised.
3. **Pranks**: use a single-shot `vm.prank` in the try statement. Do not leave a `startPrank` active while a property calls a view that is itself gated (`quoteAccruedInterest` is `onlyDcaManager`; always go through `dcaManager.getAccruedInterest`).
4. **Revert selectors**: `bytes4(err)` only when `err.length >= 4`. String reverts from the mocks (`"Insufficient output amount"`) are `Error(string)`; treat them as venue refusals, not as protocol selectors.
5. **Lending rate inside one call is constant** (LayerBank index depends only on `block.timestamp` or the override; Sovryn price only moves through env). Exact before/after comparisons inside one wrapper are therefore safe. Comparing values across two fuzzer calls is not safe.
6. **ACCOUNTS includes `feeCollector`**, which can also be an actor after rotation through `_collectorCandidate`. Per-account sums use `_accounts()` (no duplicates), and fee/buyer splits use the collector read from `BatchCtx`.
7. **Expected EXPLORATORY hits** (leads, not automatic bugs):
   - SP-64 / SP-65 (Finding 1) after a Sovryn price fall followed by a deposit inside a window;
   - GL-15's min-amount half after a 1-wei minimum;
   - SP-49 / GL-10 / GL-24 around Sovryn losses.
   Triage them against context §5 and §6.
